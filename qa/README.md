# QA · сквозные проверки интерфейса

Проверки интерфейса ИИ-трекинга в настоящем браузере: Playwright управляет
Chromium и проходит те же шаги, что пользователь — описывает задачу в чате и
подтверждает карточку параметров, наблюдает пять агентов и ленту трассы,
открывает сохранённый отчёт в ленте, открывает модалку «Настройки API», заводит
провайдера с несколькими моделями, правит их, удаляет и смотрит, что получилось в
списке моделей для проверки.

Ни одна проверка не вызывает платные внешние API: и переписка чата, и снимок
прогона подменяются через `page.route`, поэтому ни один платный вызов не уходит
наружу и ни одна строка не пишется в `runs.sqlite3`.

## Сервисы запускает не набор

QA ничего не поднимает и не останавливает. Сначала запустите приложение, потом
тесты:

```bash
make backend     # Python API на 127.0.0.1:8000
make frontend    # SvelteKit на 127.0.0.1:5173

cd qa
uv sync
uv run pytest
```

Если сервис не отвечает, набор не падает с таймаутом браузера, а предупреждает и
пропускает прогон:

```
UserWarning: Сервисы не подняты: Python API, интерфейс SvelteKit.
Ожидались http://127.0.0.1:5173 и http://127.0.0.1:8000. Запустите `make backend`
и `make frontend` — или укажите свои адреса через QA_BASE_URL и QA_API_URL.

1 skipped, 1 warning
```

## Окно браузера

По умолчанию браузер запускается **видимым** — так видно, что именно делает
тест. Спрятать окно:

```bash
QA_HEADLESS=1 uv run pytest
```

Управляет этим переопределённая в `conftest.py` фикстура плагина
`browser_type_launch_args`: она запрашивает оригинал по имени и сливает словарь
обратно, поэтому `--browser-channel` и `--slowmo` продолжают работать, а явный
флаг `--headed` сильнее переменной.

Полезные флаги:

```bash
uv run pytest --slowmo=500              # замедлить шаги
uv run pytest --browser-channel chrome  # гонять в установленном Chrome
uv run pytest -k добавить               # выбрать сценарии
PWDEBUG=1 uv run pytest                 # Playwright Inspector
```

## Работа с настоящим инстансом

Набор ходит в вашу рабочую копию приложения, а значит пишет в настоящий
`~/.config/ai-tracker/providers.json` и в настоящее системное хранилище ключей.
Чтобы это не накапливалось, фикстура `no_connection_survives_a_test` запоминает
плоский список моделей до теста и после теста удаляет только появившиеся. Группа
уходит целиком, когда удаляется её последняя модель, — вместе с ключом. Существующие
провайдеры не трогаются.

Если прогон прервать жёстко (Ctrl-C в момент сохранения), тестовый провайдер
может остаться — удалите его на странице настроек.

Проверять изолированный инстанс можно, не меняя код:

```bash
QA_BASE_URL=http://127.0.0.1:5273 QA_API_URL=http://127.0.0.1:8100 uv run pytest
```

## Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `QA_BASE_URL` | `http://127.0.0.1:5173` | Адрес интерфейса |
| `QA_API_URL` | `http://127.0.0.1:8000` | Адрес Python API — нужен для уборки подключений |
| `QA_HEADLESS` | — | `1` прячет окно браузера |

## Структура

```
qa/
├── app.py                адреса сервисов, проверка доступности, уборка за тестом
├── conftest.py           фикстуры: запущенность сервисов, видимость окна, страница
├── pages/settings.py     page object модалки настроек
├── pages/seo.py          page object чата: переписка, предложение, карточка прогона, отчёт и вкладка LLM
├── pages/fake_api.py     подменный Python API: ходы диалога, решение о запуске и ресурсы прогона
└── tests/
    ├── test_add_provider.py
    ├── test_seo.py
    ├── test_search.py
    └── test_run_history.py
```

Селекторы держатся на доступности, а не на классах: `get_by_label`,
`get_by_role`, `get_by_text`. Вёрстка использует Tailwind, и привязка к классам
ломалась бы от любой правки оформления. Карточка провайдера — это `article` с
доступным именем провайдера, её редактор помечен `data-editor`, строка модели —
`data-model-row`, а затемнение за модалкой — `data-backdrop`. В чате якорями
служат `data-chat-message`, `data-chat-proposal` и `data-chat-run`, в отчёте —
`data-seo-report`, `data-metric` и `data-candidate`, а в агентном прогоне —
`data-agent-panel`, `data-agent`, `data-budget` и `data-trace-feed`. Эти атрибуты
и нужны page object'ам, чтобы не зависеть
от вёрстки.

## Что покрыто

| Сценарий | Проверяет |
| --- | --- |
| Разделы модалки | В списке разделов нет лишних кнопок и ссылок, «Модели» открыт по умолчанию; есть «Добавить провайдера» |
| Форма создания | Поля провайдера и первой модели доступны; последнюю модель удалить нельзя |
| Конфигурация | Кнопка «Открыть конфигурацию» показывает один документ со всеми настройками — провайдеры, поисковая система и SEO-анализ — и не содержит ключей |
| Провайдер с двумя моделями | Обе модели сохраняются у одной группы с общим адресом и ключом |
| Ключ не показывается | Поле ключа пустое; ключа нет ни в тексте страницы, ни в HTML документа |
| Провайдер без ключа | Статус «Ключ не задан», после ввода ключа — «Настроен» |
| Пустой ключ | Повторное сохранение с пустым полем не теряет сохранённый ключ |
| Замена ключа | Новый ключ сохраняется, старый нигде не показывается |
| Переименование модели | Новое название видно в редакторе после повторного открытия |
| Отмена правки | «Отмена» не сохраняет черновик: повторное открытие показывает прежнее значение |
| Дополнительные настройки | Свёрнуты по умолчанию, раскрываются в адрес и строки моделей |
| Переименование провайдера | Карточка обновляется, прежнее имя исчезает |
| Небезопасный адрес | `http://localhost/...` отклоняется, провайдер не создаётся |
| Модель обязательна | Провайдер без ID модели не создаётся |
| Удаление модели | Модель уходит из редактора и не возвращается при повторном открытии |
| Удаление провайдера | Карточка исчезает, и провайдера нет в публичном списке подключений |
| Отдельные модели | Каждая модель провайдера — отдельная строка редактора с общим адресом и ключом |
| Escape | Закрывает модалку и возвращает фокус на кнопку «Настройки API» |
| Крестик и затемнение | Тоже закрывают модалку и возвращают фокус |
| Ловушка фокуса | Двенадцать нажатий Tab не выводят фокус за пределы открытой модалки |
| Повторное открытие | Сохранённый провайдер остаётся в модалке после закрытия и повторного открытия |
| BFF отвечает | `/api/providers/settings` через origin фронтенда отдаёт 200 и не содержит `api_key` |
| Консоль без ошибок | За весь сценарий в консоли браузера нет ошибок |
| Старый адрес | `/settings` отвечает 404 |

## SEO-чат, прогон и отчёт

Проверки `tests/test_seo.py`, `tests/test_search.py` и `tests/test_run_history.py`
не обращаются к Яндексу и моделям. Подменный Python API (`pages/fake_api.py`,
фикстура `api`) отвечает на все браузерные вызовы чата через `page.route`:
`POST /api/seo/chats`, сообщения и карточку предложения, снимок прогона, его
трассу, строки отчёта и отмену. Ответ служебной LLM задаётся методом
`api.route_completion`, а решение о запуске подменный сервер принимает сам — тем же
порядком веток, что и настоящий backend: неполный черновик спрашивает, «да» без
предложения не запускает, прогон финансирует только подтверждённое предложение.
Проверки, которым нужна модель в списке, создают временное подключение; его удаляет
общая фикстура.

Серверная загрузка страницы (`+page.server.ts`) ходит в Python API со стороны
SvelteKit и `page.route` не перехватывается — это нормально: список чатов и
подключения приходят от живого API. Поэтому page object после открытия страницы
начинает новый диалог, и проверка не зависит от того, что уже лежит в инстансе.
Базу `runs.sqlite3` набор не трогает вовсе.

| Сценарий | Проверяет |
| --- | --- |
| Полный диалог | Описание задачи показывает карточку предложения, «да» запускает ровно один прогон, а карточка доходит до отчёта с серверными долями и без текста модели |
| «да» без предложения | Подтверждение без карточки отвечает фиксированной фразой, прогон не создаётся |
| Ошибка без служебной LLM | Ответ `400` с понятным текстом виден в ленте |
| Вкладка «SEO-анализ» | Сохранение адреса и модели без ключа, безопасный результат «Проверить подключение» с поддержкой инструментов, ключа нет в публичном ответе |
| Прежние этапы | Прогон без агентных строк по-прежнему показывает сохранённые шесть этапов и доходит до отчёта |
| Счётчики и оценка | Видны счётчики строк и фактические `K` и `K × M` после генерации запросов |
| Пять агентов | Прогон показывает пять названных агентов с состояниями и шагами вместо списка этапов |
| Бюджет | «Использовано / предел» по страницам, поискам, ответам моделей, вызовам инструментов и передачам; исчерпание показывает баннер «остановлен по лимиту» |
| Трасса агентов | Свёрнута по умолчанию и показывает число шагов; «Показать трассу» раскрывает шаги по порядку с агентом, инструментом и безопасными аргументами, «Показать ещё» дочитывает страницу по курсору |
| Отчёт без текста модели | В отчёте нет блока «Выводы и рекомендации»: только серверные числа |
| Отмена | Кнопка отмены отправляет POST без тела и переводит прогон в «Отменён» |
| Отчёт в ленте | Завершённый прогон открывается в карточке, показывает доли, «—» для пустого знаменателя и кандидата |
| Постраничная детализация | «Показать ещё» в таблице ответов догружает следующую страницу по курсору |
| Длинный ответ модели | В таблице видно только короткое превью без разметки, «Читать полностью» открывает полный текст, отрендеренный как Markdown (заголовок, список, выделение), «Закрыть» его закрывает |
| Удаление чата | Подтверждение удаляет чат, его строка исчезает из списка, а экран сбрасывается на новый диалог |

## Версия Playwright

В `pyproject.toml` версия зафиксирована на `>=1.62,<1.63`: этот релиз использует
сборку Chromium 1234, которая уже лежит в локальном кэше браузеров. При
обновлении версии Playwright понадобится `uv run playwright install chromium`.
