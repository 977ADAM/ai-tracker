# Браузерные проверки

## Проекты: изолированный сценарий

```bash
cd qa
QA_HEADLESS=1 uv run pytest tests/test_projects.py
```

Набор сам запускает временные Python API и SvelteKit на свободных локальных
портах. Реальные API моделей заменены детерминированными адаптерами; служебная
LLM также подменена. SSR и браузер проходят настоящий BFF и сохранение SQLite.
Проверка охватывает все шесть шагов мастера: бренд/сайт, автоматически предложенные описание/варианты,
промпты, конкуренты, нейросети и отдельный ручной запуск,
импорт настоящего XLSX с группами, редактирование текста без потери группы,
конкурента без сайта, сохранение через полную форму, два замера, полный ответ
с оценкой тональности, шапку с крошками, переключение упоминаний/источников, переименование,
карточку и удаление проекта.
База временная, ключи в памяти; рабочая конфигурация и keyring не используются.

## Общие настройки: настоящий инстанс

`tests/test_add_provider.py` по-прежнему проверяет модалку общих настроек на
запущенном приложении. Запустите `make backend` и `make frontend`; по умолчанию
используются 127.0.0.1:8000/5173. Для другого инстанса задайте QA_BASE_URL/QA_API_URL.
Этот старый набор создаёт подключения в конфигурации выбранного инстанса и
удаляет только созданные им записи. Изолированный проектный сценарий обходится
без этих фикстур и без пользовательских секретов.

Прежние браузерные сценарии SEO-чата удалены вместе с заменой активного экрана;
контракты прежних API продолжают проверяться backend-тестами.
