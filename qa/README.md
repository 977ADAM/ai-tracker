# QA · сквозные проверки интерфейса

Проверки интерфейса ИИ-трекинга в настоящем браузере: Playwright управляет
Chromium и проходит те же шаги, что пользователь — заполняет SEO-форму и наблюдает
шесть этапов, открывает сохранённый отчёт и удаляет запись из SEO-истории,
открывает модалку «Настройки API», заводит провайдера с несколькими моделями,
правит их, удаляет и смотрит, что получилось в списке моделей для проверки.

Ни одна проверка не вызывает платные внешние API: ответы браузерных роутов
подменяются через `page.route`, а завершённый SEO-анализ для проверки отчёта
готовится прямо в `runs.sqlite3`.

## Сервисы запускает не набор

QA ничего не поднимает и не останавливает. Сначала запустите приложение, потом
тесты:

```bash
make backend     # Python API на 127.0.0.1:8000
make frontend    # SvelteKit на 127.0.0.1:5173

cd qa
uv sync
uv run pytest
```

Если сервис не отвечает, набор не падает с таймаутом браузера, а предупреждает и
пропускает прогон:

```
UserWarning: Сервисы не подняты: Python API, интерфейс SvelteKit.
Ожидались http://127.0.0.1:5173 и http://127.0.0.1:8000. Запустите `make backend`
и `make frontend` — или укажите свои адреса через QA_BASE_URL и QA_API_URL.

1 skipped, 1 warning
```

## Окно браузера

По умолчанию браузер запускается **видимым** — так видно, что именно делает
тест. Спрятать окно:

```bash
QA_HEADLESS=1 uv run pytest
```

Управляет этим переопределённая в `conftest.py` фикстура плагина
`browser_type_launch_args`: она запрашивает оригинал по имени и сливает словарь
обратно, поэтому `--browser-channel` и `--slowmo` продолжают работать, а явный
флаг `--headed` сильнее переменной.

Полезные флаги:

```bash
uv run pytest --slowmo=500              # замедлить шаги
uv run pytest --browser-channel chrome  # гонять в установленном Chrome
uv run pytest -k добавить               # выбрать сценарии
PWDEBUG=1 uv run pytest                 # Playwright Inspector
```

## Работа с настоящим инстансом

Набор ходит в вашу рабочую копию приложения, а значит пишет в настоящий
`~/.config/ai-tracker/providers.json` и в настоящее системное хранилище ключей.
Чтобы это не накапливалось, фикстура `no_connection_survives_a_test` запоминает
плоский список моделей до теста и после теста удаляет только появившиеся. Группа
уходит целиком, когда удаляется её последняя модель, — вместе с ключом. Существующие
провайдеры не трогаются.

Если прогон прервать жёстко (Ctrl-C в момент сохранения), тестовый провайдер
может остаться — удалите его на странице настроек.

Проверять изолированный инстанс можно, не меняя код:

```bash
QA_BASE_URL=http://127.0.0.1:5273 QA_API_URL=http://127.0.0.1:8100 uv run pytest
```

## Переменные окружения

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `QA_BASE_URL` | `http://127.0.0.1:5173` | Адрес интерфейса |
| `QA_API_URL` | `http://127.0.0.1:8000` | Адрес Python API — нужен для уборки подключений |
| `QA_HEADLESS` | — | `1` прячет окно браузера |

## Структура

```
qa/
├── app.py                адреса сервисов, проверка доступности, уборка за тестом
├── conftest.py           фикстуры: запущенность сервисов, видимость окна, страница
├── pages/settings.py     page object модалки настроек
├── pages/seo.py          page object SEO-формы, прогона, отчёта, истории и вкладки LLM
└── tests/
    ├── test_add_provider.py
    ├── test_seo.py
    ├── test_search.py
    └── test_run_history.py
```

Селекторы держатся на доступности, а не на классах: `get_by_label`,
`get_by_role`, `get_by_text`. Вёрстка использует Tailwind, и привязка к классам
ломалась бы от любой правки оформления. Карточка провайдера — это `article` с
доступным именем провайдера, её редактор помечен `data-editor`, строка модели —
`data-model-row`, а затемнение за модалкой — `data-backdrop`. В SEO-отчёте и
истории якорями служат `data-seo-report`, `data-metric`, `data-candidate` и
`data-seo-history`. Эти атрибуты и нужны page object'ам, чтобы не зависеть от
вёрстки.

## Что покрыто

| Сценарий | Проверяет |
| --- | --- |
| Разделы модалки | В списке разделов нет лишних кнопок и ссылок, «Модели» открыт по умолчанию; есть «Добавить провайдера» |
| Форма создания | Поля провайдера и первой модели доступны; последнюю модель удалить нельзя |
| Провайдер с двумя моделями | Обе модели сохраняются у одной группы с общим адресом и ключом |
| Ключ не показывается | Поле ключа пустое; ключа нет ни в тексте страницы, ни в HTML документа |
| Провайдер без ключа | Статус «Ключ не задан», после ввода ключа — «Настроен» |
| Пустой ключ | Повторное сохранение с пустым полем не теряет сохранённый ключ |
| Замена ключа | Новый ключ сохраняется, старый нигде не показывается |
| Переименование модели | Новое название видно в списке выбора на главной странице |
| Отмена правки | «Отмена» не сохраняет черновик: повторное открытие показывает прежнее значение |
| Дополнительные настройки | Свёрнуты по умолчанию, раскрываются в адрес и строки моделей |
| Переименование провайдера | Карточка обновляется, прежнее имя исчезает |
| Небезопасный адрес | `http://localhost/...` отклоняется, провайдер не создаётся |
| Модель обязательна | Провайдер без ID модели не создаётся |
| Удаление модели | Модель уходит из редактора и из списка выбора на главной странице |
| Удаление провайдера | Карточка и все его модели исчезают из списка выбора |
| Отдельные модели | Каждая модель провайдера — отдельный чекбокс на главной странице |
| Escape | Закрывает модалку и возвращает фокус на кнопку «Настройки API» |
| Крестик и затемнение | Тоже закрывают модалку и возвращают фокус |
| Ловушка фокуса | Двенадцать нажатий Tab не выводят фокус за пределы открытой модалки |
| Повторное открытие | Сохранённый провайдер остаётся в модалке после закрытия и повторного открытия |
| BFF отвечает | `/api/providers/settings` через origin фронтенда отдаёт 200 и не содержит `api_key` |
| Консоль без ошибок | За весь сценарий в консоли браузера нет ошибок |
| Старый адрес | `/settings` отвечает 404 |

## SEO-анализ, отчёт и история

Проверки `tests/test_seo.py`, `tests/test_search.py` и `tests/test_run_history.py`
не обращаются к Яндексу и моделям: браузерные `/api/seo/analyses` и
`/api/seo/settings` перехватываются через `page.route`. Форма проверяется без
полной отправки, а для проверки отчёта `tests/test_seo.py` вставляет завершённый
анализ прямо в `runs.sqlite3` из `AI_TRACKER_CONFIG_DIR` (по умолчанию
`~/.config/ai-tracker`) и удаляет данные в конце. Если базы нет, эта проверка
пропускается с сообщением. Проверки, которым нужна модель в списке, создают
временное подключение; его удаляет общая фикстура.

| Сценарий | Проверяет |
| --- | --- |
| Поля SEO-формы | Видны адрес, сфера, три ключевых запроса, услуги и подключения |
| Клиентская валидация | Пустой адрес, меньше трёх запросов, ноль услуг и ноль подключений не отправляют запрос |
| Верхняя оценка | Одно подключение показывает «23» и «20», без подключений — «0», рядом предупреждения о платных вызовах |
| Ошибка без служебной LLM | Ответ `400` с понятным текстом виден в форме, прогон не создаётся |
| Вкладка «SEO-анализ» | Сохранение адреса и модели без ключа, безопасный результат «Проверить подключение», ключа нет в публичном ответе |
| Шесть этапов | Прогон показывает шесть названных этапов, счётчики, фактические `K` и `K × M`, затем отчёт после опроса |
| Отмена | Кнопка отмены отправляет POST без тела и переводит прогон в «Отменён» |
| Отчёт из истории | Завершённый анализ открывается из истории, показывает доли, «—» для пустого знаменателя, кандидата и сохранённые строки |
| Удаление из истории | Подтверждение удаляет только конечную запись, строка исчезает из списка и из базы |
| Постраничная история | «Показать ещё» дочитывает вторую страницу по курсору |
| Постраничная детализация | «Показать ещё» в таблице ответов догружает следующую страницу |

## Версия Playwright

В `pyproject.toml` версия зафиксирована на `>=1.62,<1.63`: этот релиз использует
сборку Chromium 1234, которая уже лежит в локальном кэше браузеров. При
обновлении версии Playwright понадобится `uv run playwright install chromium`.
