# ИИ-трекинг: веб-интерфейс

SvelteKit-интерфейс узконаправленного ИИ-трекера. Компания ведётся отдельным
**проектом**: внутри проекта настраиваются бренд и сайт, промпты, конкуренты и
подключения моделей, запускается замер видимости бренда в ответах ИИ-моделей, а
результат показывается отчётом с динамикой по серии.

Python API, схема PostgreSQL и миграции описаны в
[backend/README.md](../backend/README.md); общий запуск и переменные окружения —
в [корневом README](../README.md).

## Страницы

| Маршрут                   | Что показывает                                                                             |
| ------------------------- | ------------------------------------------------------------------------------------------ |
| `/`                       | Карточки проектов: создание, удаление и запуск замера                                      |
| `/projects/new`           | Создание проекта ([ProjectForm](src/lib/components/ProjectForm.svelte))                    |
| `/projects/[id]`          | Страница проекта: шапка, запуск и отмена замера, отчёт и детализация строк                 |
| `/projects/[id]/setup`    | Мастер настройки из шести шагов ([ProjectWizard](src/lib/components/ProjectWizard.svelte)) |
| `/projects/[id]/settings` | Настройки проекта                                                                          |
| Диалог «Настройки API»    | Общие подключения моделей, поисковые системы и служебная LLM                               |

Вкладка служебной LLM в диалоге настроек исторически подписана «SEO-анализ»
(`settings-seo-tab` в [+layout.svelte](src/routes/+layout.svelte)); она настраивает
LLM, которая оценивает тональность, работает в режимах веб-поиска и генерирует
описание, промпты и конкурентов.

## Слои

```
src/
├── app.html            оболочка документа
├── app.css             Tailwind 4 и токены темы
├── routes/
│   ├── +layout.svelte  общий каркас, навигация и диалог настроек
│   ├── +page.svelte    список проектов
│   ├── +page.server.ts серверная загрузка данных
│   ├── projects/**     страницы проекта: создание, обзор, мастер, настройки
│   └── api/**          BFF: единственные HTTP-роуты, к которым обращается браузер
└── lib/
    ├── server/         серверный прокси в Python API (см. ниже)
    ├── components/     компоненты Svelte
    └── *.ts            типы, клиентские хелперы, валидация формы
```

- [python-api.ts](src/lib/server/python-api.ts) — BFF-прокси в Python API: белый
  список путей (`ApiPath`), проверка того же источника для изменяющих запросов,
  таймауты и проекции ответов поле за полем.
- [projects-api.ts](src/lib/server/projects-api.ts) — проекты, замеры и их
  публичные представления.
- [project-client.ts](src/lib/project-client.ts) — `fetch` из браузера в BFF.
- `src/lib/server/*.test.ts` и `src/lib/components/*.test.ts` — тесты Vitest рядом
  с модулями (14 файлов).
- `static/templates` — шаблоны промптов TXT/CSV/XLSX для импорта.
- Компоненты `RunHistory`, `RunResults`, `RunSummaryTable` и `SearchReport` —
  исторические остатки прежних экранов прогонов и поиска: маршрутов у них сейчас нет,
  в текущих сценариях они не используются, а сами прогоны и поиск доступны только
  через API (`/api/runs`, `/api/search`).

Браузер обращается **только** к этому приложению: страницы и `api/**/+server.ts`
проксируют запросы в Python API на стороне сервера, поэтому CORS не нужен, а ключи
API в браузер не попадают.

## Запуск

```bash
npm ci
npm run dev        # http://127.0.0.1:5173
```

Нужен работающий Python API на `http://127.0.0.1:8000` (`make backend` из корня
репозитория, предварительно `make migrate`). Из корня доступны `make frontend`
(dev), `make build` (сборка) и `make frontend-prod` (запуск собранного).

## Переменные окружения

Все они читаются **на сервере** (BFF и adapter-node), в браузер не попадают.

| Переменная             | Назначение                                                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AI_TRACKER_API_URL`   | Адрес Python API для серверных запросов. По умолчанию `http://127.0.0.1:8000`; допустим только `http` и хост из списка ниже                             |
| `AI_TRACKER_API_HOSTS` | Дополнительные хосты, к которым BFF вправе обращаться, через запятую; loopback (`127.0.0.1`, `localhost`) разрешён всегда, в compose добавлен `backend` |
| `AI_TRACKER_BASE_PATH` | Базовый путь сборки (SvelteKit `paths.base`); в образе — `/clustering/tracker`                                                                          |
| `ORIGIN`               | Публичный origin для абсолютных ссылок и перенаправлений adapter-node                                                                                   |
| `HOST`, `PORT`         | Адрес и порт сервера Node; в образе `0.0.0.0:3001`                                                                                                      |

## Сборка и Docker

`npm run build` собирает приложение через `@sveltejs/adapter-node` в `build/`;
запуск — `node build/index.js`. [Dockerfile](Dockerfile) собирает образ в два шага
(`node:22-alpine`), ставит только production-зависимости и стартует от
непривилегированного пользователя на порту `3001`. `docker compose` поднимает его
вместе с backend и PostgreSQL; интерфейс публикуется на `127.0.0.1:3001`.

## Проверки

```bash
npm run check         # svelte-check: типы Svelte и TypeScript
npm run lint          # ESLint (flat-конфиг, typescript-eslint, eslint-plugin-svelte)
npm run lint:fix      # ESLint с автоисправлениями
npm run format        # Prettier: Svelte и Tailwind
npm run format:check  # проверка форматирования без записи
npx vitest run        # модульные тесты и тесты компонентов
```

Из корня то же самое делают `make check` (types, format-check, lint), `make types`,
`make lint`, `make format-check` и `make build`.

## Правила разработки

- Новый вызов Python API добавляется в BFF: путь попадает в `ApiPath`
  ([types.ts](src/lib/types.ts)) и в проверку `validPath` ([python-api.ts](src/lib/server/python-api.ts)),
  а браузер ходит только в `src/routes/api/**`. Произвольный хост с сервера не
  вызывается: `AI_TRACKER_API_URL` проверяется по списку хостов.
- Ответы Python API проецируются поле за полем (`public*`-функции): лишние поля,
  ключи и внутренние идентификаторы в браузер не проходят.
- Запросы, меняющие состояние, принимаются только с тем же источником
  (`sameOriginRequest`), поэтому `localhost` и `127.0.0.1` работают одинаково.
- Ограничения BFF: тело запроса ≤ 64 КиБ (исключение — `POST /api/projects/import-prompts`:
  до 512 КиБ на файл промптов), CSV ≤ 5 МиБ, обычный таймаут 10 секунд, проверка
  служебной LLM — 120 секунд.
- Форматирование — Prettier (плагины Svelte и Tailwind, ширина 100), стиль — ESLint;
  перед коммитом достаточно `make check` из корня репозитория.
