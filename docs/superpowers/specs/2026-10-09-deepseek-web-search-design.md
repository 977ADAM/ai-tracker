# DeepSeek: ответы с веб-поиском и источниками

Дата: 2026-10-09. Статус: спецификация для согласования.

## Цель и границы этапа

Пользователь выбрал первым этапом встроенный веб-поиск DeepSeek через прямое
подключение к `api.deepseek.com`. Приложение должно сохранять ответ модели и
раздельно показывать найденные страницы и действительно процитированные источники.
Упоминание бренда и цитирование его сайта становятся разными метриками.

Основной интерфейс остаётся чатом с подтверждением предложения перед прогоном.
Этот этап не увеличивает набор промптов, не добавляет расписание, сравнение замеров,
тональность, словарь брендов или сбор ответов с сайта chat.deepseek.com.
Результат характеризует API DeepSeek с включённым поиском.

## Проверенные основания и ограничение доказательств

Официальный DeepSeek Harness реализует встроенный поиск через
`https://api.deepseek.com/anthropic/v1/messages`, инструмент
`web_search_20250305`, структурированные блоки `web_search_tool_result` и цитаты
в `text.citations`. Обычный Chat Completions адаптер приложения этого не делает.

Источники:

- https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/web/web-search-deepseek/src/provider.ts
- https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/web/web-search-deepseek/src/types.ts
- https://api-docs.deepseek.com/quick_start/agent_integrations/claude_code/

Доступность поиска для конкретной настроенной модели и ключа пока не проверена
живым вызовом. При реализации нужен один ограниченный контрольный запрос через
существующее подключение. Ключ читается сервером из прежнего хранилища и не выводится.
Нельзя объявлять поддержку проверенной только по тестам на подменных ответах.

## Выбранный подход

Использовать встроенный поиск DeepSeek и его структурированные цитаты. Альтернатива
«наш поиск, затем ответ DeepSeek» меняет измеряемый сценарий, поэтому в этап не входит.
Автоматического перехода к собственному поиску при ошибке нет.

Добавить отдельный адаптер для SEO-ответов с поиском, сохранив текстовый контракт
обычных проверок `/api/check` и `/api/runs`, а также служебную LLM чата и агентов.
Служебная LLM не является проверяемой моделью и не получает этот режим автоматически.

## Настройки подключения

У группы провайдера появляется `answer_mode`: `text` или `deepseek_web`.
В интерфейсе — выбор «Обычный ответ» / «Веб-поиск DeepSeek и источники».
Режим действует на SEO-проверки всех моделей этой группы; в карточке предложения
рядом с выбранными моделями видна отметка режима.

По умолчанию существующие и новые подключения используют `text`.
`deepseek_web` разрешён только для HTTPS-адресов обычного Chat Completions API
на точном хосте `api.deepseek.com`, без нестандартного порта: пути
`/chat/completions` и `/v1/chat/completions`.
Запросы поиска идут на фиксированный официальный Messages endpoint с тем же ключом.
Модель берётся из выбранной строки настройки, без скрытой замены на другую модель.
Отказ API из-за неподдерживаемой модели показывается как ошибка строки.

Режим сохраняется в JSON-метаданных группы, публичных схемах, конфигурации и
проекциях отдельных подключений. Неизвестное значение отклоняется сервером.
Изменение режима или модели во время анализа не меняет уже запущенный прогон:
SEO-сервис сохраняет и использует снимок не секретных параметров подключений
при старте. Секреты в снимок не попадают.

## Контракт ответа и адаптер

Для SEO-вызовов ввести структурированный результат:

- `text`: полный видимый ответ, собранный из текстовых блоков в исходном порядке;
- `answer_mode`: режим вызова;
- `search_status`: `not_requested`, `completed` или `error`;
- `search_results`: страницы из успешных блоков поиска, URL и название;
- `citations`: цитаты текстовых блоков, URL, название при наличии,
  процитированный фрагмент при наличии, номер текстового блока и порядок цитаты;
- `model`: фактическая модель ответа при наличии, иначе запрошенная;
- `search_calls`: число наблюдаемых поисковых вызовов, если API его возвращает.

Текстовый адаптер возвращает `not_requested` и пустые списки. Старый метод
`answer(prompt) -> str` продолжает обслуживать прежние сценарии.

DeepSeek-адаптер отправляет Messages запрос с поисковым инструментом и
`max_uses=1`, максимумом ответа 4096 токенов, инструкцией выполнить поиск и
ответить с цитатами. Наличие поисковых блоков проверяется по ответу API.
Таймаут полного вызова — 120 секунд; перенаправления запрещены.
Ответ с `pause_turn` или иным незавершённым выполнением не считается завершённым;
автоматического продолжения с новым платным запросом в этом этапе нет.

Ссылки принимаются только из структурированных полей API. Ссылки, написанные
моделью в тексте, не превращаются в цитаты. При наличии поисковых результатов
и отсутствии цитат успешный завершённый ответ имеет ноль цитат.
Поиск без результатов также является успешным, если API вернул успешный пустой
блок поиска. Отсутствие поискового блока или ошибка любого поискового блока
означает ошибку строки, даже если модель успела вернуть текст.

## Нормализация источников

Разрешены только публичные HTTP(S) URL без учётных данных. Некорректные ссылки
и небезопасные схемы исключаются; сервер не загружает эти страницы.
Проверка публичности URL использует имеющиеся правила проекта, без дополнительного
сетевого обхода и без утверждения, что страница доступна.

Повторяющиеся страницы поиска объединяются по URL; порядок первого появления
сохраняется. В цитатах сохраняются все вхождения, а список источников для показа
объединяется по URL в порядке первого цитирования. Фрагмент URL не участвует
в идентичности страницы; query-параметры сохраняются.

Домен приводится к каноническому виду средствами проекта; сайт сопоставляется
с его поддоменами по существующим правилам. Название берётся из цитаты, затем
из поискового результата того же URL, затем показывается домен.
Порядок цитат не называется рейтингом или поисковой позицией.

## Хранение и API

Аддитивная миграция общего SQLite-файла до версии 6. Координатор инициализации
и все репозитории общего файла должны принимать версию 6; новые поля создаёт
SEO-репозиторий до загрузки или восстановления анализов.

У модельной строки хранить режим, статус поиска, списки результатов и цитат,
модель и наблюдаемое число поисковых вызовов. Списки — JSON с серверной валидацией.
У анализа хранить снимок параметров выбранных подключений.
Ответ и источники записываются одной транзакцией, удаляются вместе с анализом
и возвращаются существующим постраничным ресурсом `rows?kind=model`.

Старые строки получают режим `text`, статус `not_requested` и пустые списки.
Исторические запущенные анализы без снимка остаются в прежнем текстовом режиме;
переключение настройки не превращает их восстановление в поиск.
Новых маршрутов для чтения источников не требуется. Дополнения схем API и типов
frontend не удаляют существующие поля. Источники не добавляются в общий снимок
анализа с полными текстами: детализация остаётся постраничной.

## Метрики

Существующие метрики упоминания названия и домена остаются текстовыми.
Добавить для каждой модели и сайта метрику `citation`:

- знаменатель — завершённые успешные ответы с `search_status=completed`;
- успех — хотя бы одна структурированная цитата сайта или его поддомена;
- доля — успехи / знаменатель; при пустом знаменателе `null`;
- средний порядок — среднее место первого домена сайта в списке уникальных
  цитируемых доменов каждого ответа, только для ответов, где сайт процитирован.

Для выбранных конкурентов считать такую же метрику по их доменам.
Разрезы сайта по брендовым/небрендовым запросам, категориям и услугам включают
цитирование по тем же правилам. Ошибки и старые текстовые ответы не входят
в знаменатель цитирования. Числа считает сервер по сохранённым строкам.
Новый агент не нужен; агент отчёта получает новые агрегаты и смысл показателей.

## Интерфейс

В отчёте добавить «Цитирование сайта» с долей и числом успешных проверок,
а также «Средний порядок первого цитирования домена». Для пустого знаменателя
показывать «—» и объяснение «Нет данных о цитировании».

Просмотр ответа доступен также для короткого текста, если есть источники
или информация о поиске. В существующем окне ответа показывать режим,
полный текст и два списка: «Процитированные источники» и свёрнутый
«Найденные страницы». Ссылки кликабельные, с безопасной схемой,
`noopener noreferrer`; сохраняется очистка Markdown и управление фокусом.
Цитаты привязаны к соответствующему текстовому блоку; при отсутствии точных
смещений не придумывать расположение цитаты внутри предложения.

## Стоимость, ошибки и повторные вызовы

Предел пяти модельных ответов на прогон сохраняется. Для каждого ответа
в режиме DeepSeek допускается не больше одного внутреннего поискового вызова,
то есть верхняя оценка — пять поисковых вызовов DeepSeek на прогон.
В предложении это показывается отдельно от пяти запросов Яндекса.
Это предел числа операций, а не обещание фиксированной стоимости: обработка
поиска может включать дополнительное использование токенов со стороны провайдера.

Поисковый адаптер не делает автоматических повторных платных запросов при
ошибке или таймауте. Существующая защита сохранённой пары «запрос × подключение»
от повторного вызова сохраняется; она не даёт новой гарантии ровно одного
платного вызова при аварии процесса между отправкой запроса и записью результата.

Ошибки авторизации, лимита, неподдерживаемой модели, поиска, формата ответа
и таймаута имеют фиксированные безопасные русские сообщения. Тела ошибок
провайдера и ключи не возвращаются в публичный API и не записываются в трассу.
Ошибка одной модели не отменяет остальные проверки.

## Проверка результата

- Адаптер: ответ с цитатами, повторяющиеся URL, пустой поиск, поиск без цитат,
  отсутствие поиска, ошибка инструмента, незавершённый ответ, HTTP-ошибки и таймаут.
- Домен: упоминание без цитирования, цитирование без названия бренда, поддомены,
  порядок уникальных доменов, небезопасные URL, пустой знаменатель и разрезы.
- Хранилище: миграция версии 5 → 6, старые данные, атомарность записи,
  чтение страниц, удаление, снимок параметров и восстановление старого анализа.
- Сервис/API: режим проходит от настройки до проверки; служебная LLM и старые
  сценарии не используют поиск; лимит и отсутствие повторных платных запросов.
- Frontend: настройка режима, отметка предложения и бюджет, метрики,
  окно короткого ответа с источниками, безопасные ссылки и состояние «нет данных».
- Один контрольный запрос к реальному API DeepSeek проверяет модель, выполнение
  поиска и формат ответа. Отсутствие цитат само по себе не является ошибкой поиска.

README и tech.md обновляются с различием «упоминание / цитирование», бюджетом
DeepSeek и оговоркой, что измеряется API, а не потребительский чат провайдера.

## Критерий завершения

Пользователь выбирает режим поиска у прямого подключения DeepSeek, подтверждает
предложение в чате и получает сохранённый ответ с отдельными источниками.
Отчёт различает упоминание и цитирование; повторное открытие воспроизводит
сохранённые данные. Совместимость старых ответов и сценариев подтверждена тестами,
а доступность поиска для выбранной модели подтверждена контрольным вызовом.
