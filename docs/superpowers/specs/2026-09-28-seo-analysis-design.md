# SEO-анализ сайта и конкурентов — дизайн

## Статус и цель

Дизайн согласован в чате 2026-09-28; ожидает ревью письменной спецификации.

Добавить в локальный, однопользовательский AI Tracker основной сценарий SEO-анализа сайта и конкурентов. Пользователь указывает сайт, нишу, три исходных поисковых запроса и услуги. LangChain анализирует публичное содержимое сайта, находит конкурентов и готовит ограниченный пользователем набор запросов. Эти запросы проверяются в Яндексе и выбранных пользователем существующих ИИ-подключениях. Прогон и итоговый отчёт доступны после перезапуска приложения.

Успешный результат — сохранённый отчёт, который показывает органическую видимость сайта и конкурентов в Яндексе, частоту их упоминаний в ответах выбранных моделей, исходные запросы и ошибки отдельных источников. Числа в сводке должны выводиться из сохранённых строк результатов, а не из свободного пересказа модели.

## Согласованные продуктовые решения

- SEO-анализ заменяет текущую основную форму на домашней странице.
- Существующие прямые API и таблицы старых прогонов сохраняются. SEO-прогоны хранятся и отображаются в отдельной истории; старые результаты не мигрируются в новый формат.
- Поисковая система первой версии — Яндекс. География по умолчанию — вся Россия (регион 225).
- В форме есть URL главной страницы, сфера бизнеса, ровно три запроса для поиска конкурентов, названия услуг и количество генерируемых запросов.
- Название компании и услуги извлекаются из сайта до платных поисковых/потребительских модельных проверок; имя компании можно поправить, а предложенные услуги можно принять, удалить или дополнить вручную введёнными.
- Пользователь выбирает подключённые в приложении модели для проверки ответов. По умолчанию выбираются стандартные подключения из текущей настройки формы.
- Отдельная модель для LangChain настраивается независимо: OpenAI-совместимый API, адрес, модель и ключ.
- Число генерируемых запросов задаётся при каждом запуске. Предложенный диапазон — 5–100, значение по умолчанию — 20.
- Процесс фиксированный и пошаговый, без свободного цикла автономных агентов. LangChain используется для извлечения структурированных сведений, классификации/генерации запросов и итогового текстового резюме.

## Пользовательский сценарий

1. Пользователь вводит адрес главной страницы, сферу бизнеса, три различных seed-запроса, список услуг и лимит генерации. Выбирает одно или больше подключённых ИИ-подключений.
2. До основного запуска сервер выполняет безопасный предварительный просмотр сайта: определяет название компании и предлагает найденные на сайте услуги. Пользователь исправляет название, редактирует/подтверждает услуги и запускает анализ.
3. Страница создаёт SEO-прогон и показывает ход этапов: поиск конкурентов, генерация запросов, ответы моделей, выдача Яндекса, формирование отчёта.
4. Пользователь видит готовый отчёт и может открыть его позже из истории.

Форма показывает оценку обращений перед запуском. При лимите `N` и `M` выбранных модельных подключениях планируется `3 + N` поисковых запросов в Яндекс и `N × M` запросов к потребительским моделям. Запрос к LangChain для извлечения сведений сайта, генерация и сводный текст показываются отдельно; денежная стоимость не обещается, так как тарифы источников различаются.

## Поток анализа

### Предварительный просмотр сайта

Отдельный BFF/API-вызов получает главную страницу и ограниченное число связанных страниц того же сайта, извлекает заголовки и основной текст и возвращает предлагаемое название компании и услуги. LangChain структурирует извлечённый текст; это происходит до поиска и ответов выбранных моделей. Пользователь может отредактировать название, а предлагаемые услуги представлены как набор отметок: отмеченные услуги объединяются с введёнными вручную и дедуплицируются. Если имя не обнаружено, пользователь вводит его вручную до запуска. Данные страницы — недоверенный контент: текст не может менять system prompt, выбирать произвольные инструменты или инициировать сетевые обращения.

### Поиск конкурентов

Каждый из трёх seed-запросов отправляется в Яндекс с регионом 225. Из первых десяти органических результатов извлекаются внешние домены; хост пользователя и его поддомены исключаются. Кандидаты ранжируются по числу seed-запросов, в выдаче которых они встретились, затем по средней позиции. Домены из двух или трёх выдач отмечаются как повторяющиеся кандидаты; остальные показываются как разовые результаты. В отчёте для каждого кандидата сохраняются домен, имя из заголовка результата (если доступно, иначе hostname), число появлений, средняя позиция и исходные seed-запросы.

В первой версии «конкурент» означает домен, повторно представленный в органической выдаче по seed-запросам. Отчёт маркирует список как кандидатов на конкурентов и показывает evidence, чтобы пользователь мог оценить справедливость сравнения; обещания, что любой найденный домен является прямым конкурентом, нет.

### Генерация запросов

LangChain получает подтверждённые пользователем нишу и услуги, три seed-запроса, название компании и домены кандидатов. Структурированный результат включает запрос, категорию и связанную услугу. Категории первой версии: коммерческие, информационные и сравнительные. Модель генерирует до заданного лимита уникальных запросов; сервер проверяет схему, длину и дубликаты до любого платного запуска.

### Проверки поиска и моделей

Один и тот же набор сгенерированных запросов отправляется:

- в текущий Yandex Search API по всей России, чтобы определить наличие сайта и кандидатов в первых десяти результатах и их позиции;
- в каждое выбранное существующее подключение модели, чтобы получить ответы на поисковые вопросы и сохранить их для отчёта.

Подключение LangChain используется для обработки сайта, генерации и резюме; оно не подменяет выбранные потребительские модели в метрике упоминаний.

### Отчёт

Сводка рассчитывается только по завершённым строкам:

- Яндекс: доля успешных запросов, где сайт/домен конкурента найден в топ-10, и средняя позиция среди найденных.
- ИИ: доля успешных ответов, содержащих нормализованное название компании или домен сайта; тот же расчёт по имени результата поиска/домену кандидата, отдельно по провайдеру и категории.
- Детализация: запрос, категория/услуга, источник, позиция или ответ, результат упоминания, статус и безопасное описание ошибки.
- Текстовое резюме от LangChain опирается на уже собранные строки и сводные числа. Оно не заменяет и не изменяет числовые метрики.

Для поиска упоминаний применяется нормализованное нечувствительное к регистру совпадение целой фразы для названия компании и имени/домена кандидата. Автоматический подбор неуказанных пользователем псевдонимов не обещается; извлечённое название компании можно поправить до запуска.

## Архитектура и границы компонентов

### Frontend

- Заменить основной сценарий на главной странице SEO-формой.
- Добавить предварительный просмотр/редактирование сведений сайта, выбор лимита и существующих моделей, оценку числа запросов, прогресс этапов и SEO-историю.
- Добавить подробный SEO-отчёт с агрегатами, конкурентными доменами, результатами по запросам и сохранёнными модельными ответами.
- Добавить настройки LangChain в существующий раздел настроек.
- Оставить старые BFF и API-маршруты работоспособными; новая форма использует только новые SEO-маршруты.

### Backend

Добавить отдельные схемы, правила домена, сервисы и маршруты для предпросмотра сайта и SEO-прогонов. SEO-оркестратор координирует последовательные этапы подготовки и независимые ветви Яндекса/моделей, не расширяя смысл старого `RunService`.

Вынести в интеграционные порты:

- fetcher публичных страниц с ограниченным обходом и извлечением текста;
- LangChain-клиент для заданного OpenAI-совместимого адреса, ключа и модели;
- переиспользуемый Yandex Search Gateway с сохранением документов, требуемых для позиций и evidence;
- существующие адаптеры выбранных модельных подключений.

### Настройки LangChain

Добавить независимые настройки endpoint и model плюс секретный API-ключ. Публичный GET возвращает адрес/модель и признак наличия ключа, но никогда не ключ. API-ключ хранится через существующую абстракцию системного хранилища секретов. При сохранении пустой ключ не стирает действующий; отдельная команда сброса удаляет ключ. Заданный пользователем адрес ограничивается HTTP(S) и проверяется при тестовом вызове модели.

### Хранение и жизненный цикл

В существующую SQLite-базу добавить отдельные таблицы анализа: входные параметры/статус/времена; этапы; найденные домены и evidence; сгенерированные запросы; строки Yandex; ответы выбранных моделей; сводный текст. Сохранять каждый результат сразу после получения, не записывать API-ключи.

Перезапуск не должен терять законченные строки. Оставшиеся на момент запуска незавершённые SEO-прогоны помечаются прерванными, а готовая детализация остаётся читаемой. Ошибка сохранения блокирует последующие внешние вызовы прогона. История получает постраничную загрузку и удаление завершённой записи; удаление активного прогона запрещено.

## Валидация, ошибки и безопасность

- Требовать корректный публичный HTTP(S) URL, сферу, ровно три непустых различных seed-запроса, не менее одной услуги и не менее одного подключения модели.
- Лимит генерации: 5–100, по умолчанию 20; для нового SEO API это отдельный лимит, старое ограничение прямого API не меняется. Ограничения Яндекса по длине/словам проверяются до отправки.
- Ограничить предварительный обход 20 HTML-страницами введённого хоста и его поддоменов, 1 MiB на ответ и 60 секундами на весь обход. Следовать только HTTP(S), не выполнять JavaScript и не отправлять формы.
- До каждого соединения и после каждого перенаправления разрешать только публичные IP-адреса; блокировать loopback, private, link-local, multicast, reserved и локальные имена. Ссылки и перенаправления разрешены только на введённый хост или его поддомены. Ограничить число перенаправлений пятью. Соблюдать robots.txt и не обходить CAPTCHA или аутентификацию.
- Тайм-аут одного сетевого соединения — 10 секунд. Контент и редиректы ограничиваются общим timeout обхода.
- Результаты одного источника не маскируют сбой другого. Ошибка URL/обхода не создаёт платные поисковые/модельные задачи. Отсутствующий ключ/ошибка LangChain останавливает генерацию; ошибка выбранного потребительского провайдера не блокирует другие провайдеры и Яндекс.
- Невалидный структурированный ответ LangChain допускает одну повторную генерацию/валидацию, затем этап помечается ошибочным. Ошибки никогда не трактуются как отрицательное упоминание или отсутствие сайта.
- Секреты, upstream response bodies и внутренние исключения не попадают в API-ответы, историю или логи.

## Передаваемые данные

- Текст сайта отправляется только отдельно настроенному LangChain-провайдеру для извлечения сведений и генерации структурированных результатов.
- Сгенерированные запросы отправляются в подключённые потребительские модельные API. Ответы хранятся локально; итоговое текстовое резюме LangChain получает только агрегированные метрики, а не полные ответы.
- Поисковые запросы и домен сайта отправляются в Yandex Search API.
- LangSmith tracing по умолчанию выключен. Отладка не должна сохранять секреты или полные ответы без отдельной настройки пользователя.

## Контракты верхнего уровня

Названия являются проектными, точные поля закрепляются в реализации и OpenAPI.

- `POST /api/seo/site-preview` — принимает URL и возвращает извлечённое название, услуги и безопасную причину неудачи.
- `GET/PUT /api/seo/settings` и `DELETE /api/seo/settings/credentials` — настройки модели LangChain без возврата секрета.
- `POST /api/seo/analyses` — валидирует вход и создаёт долговечный анализ; ответ содержит ID и статус.
- `GET /api/seo/analyses` — история с курсором.
- `GET /api/seo/analyses/{id}` — прогресс или сохранённый отчёт.
- `DELETE /api/seo/analyses/{id}` — удаление только завершённого/прерванного анализа.

SvelteKit BFF проксирует эти маршруты к FastAPI по существующей схеме и не принимает решения по секретам.

## Проверка качества

Проверка выполняется с фиктивными fetcher, Yandex gateway, LangChain-моделью и потребительскими моделями; автоматизация не вызывает платные внешние API.

- Правила: URL/IDN/редиректы, три seed-запроса, лимит 5–100, дубликаты, ограничения длины, агрегация доменов, ранжирование и процентные метрики.
- API/сервис: последовательность этапов, частичное сохранение, отказ платных вызовов при ошибке предпросмотра, независимость ветвей, скрытие секретов, восстановление после перезапуска и прерывание незавершённого прогона.
- Безопасность fetcher: блокирование localhost/private IP, DNS и redirect-проверки, запрет перехода на другой домен, размер и timeout.
- UI: предпросмотр и исправление имени, редактирование услуг, estimate объёма вызовов, выбор модели и лимита, прогресс, частичные ошибки, открытие сохранённого отчёта из истории.
- Регрессия: старые `/api/check`, `/api/search`, `/api/runs` и старое хранилище продолжают проходить действующую проверку совместимости.

## Вне первой версии

- Google/Bing и другие поисковые системы; регионы, кроме всей России.
- Плановые/периодические запуски, multi-user/accounts, биллинг и облачное развёртывание.
- Автоматическое изменение сайта, CMS-интеграции, линкбилдинг и выдача юридических/коммерческих рекомендаций.
- Гарантия полноты краулинга, прямой конкурентности каждого найденного домена или стабильности выдачи/ответов модели во времени.

## Обоснование использования LangChain

Фиксированные шаги лучше соответствуют задаче, чем автономный цикл агента: порядок действий и платные вызовы известны заранее. LangChain предоставляет модельный интерфейс, tool/chain composition и структурированный результат; документация определяет агент как модель, вызывающую инструменты в цикле, и предлагает `create_agent` для управляемого цикла инструментов. В этом продукте не нужен свободный цикл: отдельные типизированные операции дают предсказуемый оркестратор. Официальная документация: [Agents](https://docs.langchain.com/oss/python/langchain/agents), [LangChain overview](https://docs.langchain.com/oss/python/langchain/overview).
