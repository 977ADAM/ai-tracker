# Настройки поисковых систем

## Цель и границы

Добавить в модальное окно настроек API вкладку «Поисковые системы». В первой версии она управляет только Яндексом: его доступностью в форме регионов и параметрами подключения к Yandex Search API. Google и другие поисковые системы в эту работу не входят.

Существующая форма запуска передаёт поисковик для каждого региона в `region_targets`. Этот контракт сохраняется. Backend должен проверять доступность поисковика самостоятельно, так как клиент может отправить устаревший или составленный вручную запрос.

## Пользовательский интерфейс

- В боковой навигации настроек рядом с «Модели» появляется вкладка «Поисковые системы».
- Вкладка содержит карточку Яндекса с переключателем доступности, полем API-ключа, полем ID каталога и состоянием подключения.
- Яндекс включён по умолчанию, чтобы сохранить поведение существующих установок.
- Выключенный Яндекс отсутствует среди доступных вариантов для новых поисковых запусков. При отсутствии включённых поисковиков пользователь по-прежнему может проверять только модели.
- Сохранение настроек обновляет доступные варианты на основной форме без полной перезагрузки страницы.
- Уже запущенный прогон продолжает использовать настройки, захваченные при запуске. Изменение или отключение настроек применяется к новым прогонам.

## Хранение и разрешение настроек

Настройки поисковика отделены от настроек провайдеров моделей. Метаданные Яндекса (флаг доступности и ID каталога) хранятся в локальном файле конфигурации в `AI_TRACKER_CONFIG_DIR`. API-ключ хранится в системном хранилище учётных данных через существующий интерфейс `SecretStore`/`keyring` и никогда не записывается в JSON.

Для API-ключа и ID каталога поддерживается такой приоритет:

1. Значение, заданное через интерфейс и сохранённое приложением.
2. Переменные окружения из текущей конфигурации: `YANDEX_SEARCH_API_KEY` / `API_KEY` и `YANDEX_SEARCH_FOLDER_ID` / `FOLDER_ID`.

Явная переменная окружения продолжает иметь приоритет над одноимённым значением из `.env`, как и сейчас. Пустое поле API-ключа при сохранении означает «не менять сохранённый ключ». Отдельное действие сбрасывает сохранённые пользовательские учётные данные к значениям окружения; флаг доступности при этом не меняется.

Если файл конфигурации поиска ещё не создан или в нём нет поля `enabled`, эффективное значение `enabled` равно `true`. Поэтому прежние установки продолжают показывать Яндекс без предварительного открытия вкладки. После явного выключения значение сохраняется как `false`.

Состояние подключения показывает наличие эффективного ключа и ID каталога. ID каталога не считается секретом и возвращается в публичном состоянии; API-ключ не раскрывается. Если поисковик включён, но учётные данные отсутствуют, Яндекс остаётся доступным для выбора; при запуске backend возвращает существующую понятную ошибку о недостающих настройках.

## API и применение

Добавляется отдельный ресурс `GET/PUT /api/search/settings`, доступный браузеру через серверный BFF SvelteKit. GET возвращает объект с отдельными источниками ключа и ID каталога, поскольку они могут быть заданы независимо. Контракт GET:

```json
{
  "yandex": {
    "enabled": true,
    "folder_id": "b1g...",
    "has_api_key": true,
    "api_key_source": "ui",
    "folder_id_source": "env"
  }
}
```

`folder_id` — эффективный ID каталога или `null`, если он не задан. `has_api_key` сообщает только наличие эффективного API-ключа; самого ключа в ответе нет. `api_key_source` и `folder_id_source` независимо принимают значения `ui`, `env` или `none` согласно описанному приоритету. При источнике `none` эффективное значение отсутствует. PUT сохраняет разрешённые настройки и секрет.

Тело `PUT /api/search/settings` поддерживает частичное обновление и принимает только переданные поля:

```json
{
  "enabled": false,
  "api_key": "новый ключ",
  "folder_id": "b1g..."
}
```

Допустимы только эти поля: `enabled` — boolean, `api_key` — string, `folder_id` — string. Все поля необязательны; например, `{"enabled": true}` меняет только доступность Яндекса. Отсутствующие поля не меняются. Непустые `api_key` и `folder_id` заменяют соответствующие пользовательские значения. Пустые строки для обоих полей означают «не менять»; `null` и неизвестные поля отклоняются. Это исключает неоднозначность между пустым полем и сбросом.

Сброс пользовательских учётных данных выполняется отдельным `DELETE /api/search/settings/credentials`. Он всегда удаляет оба сохранённых в интерфейсе переопределения — API-ключ и ID каталога; частичного сброса нет. Если переопределений нет, DELETE является no-op, а не ошибкой. В обоих случаях ответ `200` содержит актуальное публичное состояние в формате GET. После удаления каждого переопределения применяется соответствующее значение окружения. Если окружение также не задаёт значение, источник становится `none`; тогда `has_api_key` равен `false`, а `folder_id` равен `null`. `enabled` при сбросе сохраняется.

Сервис настроек поиска использует отдельное хранилище метаданных и существующий `SecretStore`. После сохранения новые прогоны сразу используют новый gateway/configuration без перезапуска приложения. При создании прогона его конфигурация и gateway фиксируются для всей работы, чтобы изменение настроек не меняло учётные данные посреди уже выполняющихся пар «вопрос × регион».

Запрос запуска поиска отклоняется с безопасной ошибкой, если Яндекс выключен. Существующие env-настройки остаются совместимыми и продолжают настраивать Яндекс без открытия вкладки.

## Проверки и критерии готовности

- API сохраняет состояние доступности, ID каталога и ключ; публичные ответы и ошибки не раскрывают секрет.
- GET корректно показывает независимые источники ключа и ID каталога, в том числе смешанный вариант `ui` + `env`.
- Частичный PUT обновляет только переданные поля; пустые строки не очищают учётные данные, `null` отклоняется.
- DELETE всегда сбрасывает оба пользовательских переопределения вместе, не меняя `enabled`; частичный сброс не поддерживается.
- DELETE без сохранённых переопределений успешен и возвращает `200` с текущим состоянием.
- После DELETE при отсутствии соответствующих env-значений источник равен `none`, `has_api_key` равен `false`, а `folder_id` равен `null`.
- При отсутствующем файле настроек, как и при отсутствующем поле `enabled`, Яндекс включён.
- Пустой ключ оставляет сохранённый ключ без изменений; явный сброс возвращает разрешение к окружению.
- Старые переменные окружения продолжают создавать работающую конфигурацию Яндекса.
- Запросы от старых клиентов без `region_targets` сохраняют прежнее поведение, если Яндекс включён.
- Backend не запускает новые поисковые прогоны, когда Яндекс выключен.
- Форма регионов показывает только включённые поисковики и обновляется после сохранения настроек.
- Уже запущенный прогон использует прежний снимок конфигурации после её изменения.
- В модальном окне доступны навигация и содержимое обеих вкладок с корректными состояниями для вспомогательных технологий.
- Существующие проверки backend и frontend остаются зелёными; добавлены тесты для API, хранилища секрета, env-fallback, вкладки и динамического списка поисковиков.
