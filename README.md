# ИИ-трекинг: проверка бренда в ответах ИИ

Локальное приложение показывает, упоминают ли GigaChat, DeepSeek и подключённые OpenAI-совместимые модели ваш бренд в ответах на заданные вопросы. Это проверка **ответов API моделей**, а не поисковой выдачи или цитирования сайта.

## Запуск

Нужны Python 3.13+, [uv](https://docs.astral.sh/uv/) и Node.js 20.19+. Установите зависимости:

```sh
make install
```

Запустите сервисы в разных терминалах:

```sh
make backend
```

```sh
make frontend
```

Исходники веб-интерфейса, `package.json` и `package-lock.json` находятся в `frontend/`, Python API и его тесты — в `backend/`. Каждая команда запускает только свой сервис; остановите его через Ctrl+C в соответствующем терминале.

Откройте [http://127.0.0.1:5173/settings](http://127.0.0.1:5173/settings), настройте GigaChat или DeepSeek и вернитесь к проверке. SvelteKit показывает страницы и принимает запросы браузера на порту 5173. Python API работает только на `127.0.0.1:8000`; сервер SvelteKit передаёт ему запросы. Браузер не обращается к Python напрямую. Для другого локального порта Python укажите серверную переменную `AI_TRACKER_API_URL=http://127.0.0.1:НОМЕР_ПОРТА`.

Для запуска собранной версии сначала выполните `make build`, затем запустите `make backend` и `make frontend-prod` в разных терминалах. Она открывается по адресу [http://127.0.0.1:5173](http://127.0.0.1:5173).

Ключ GigaChat берётся в личном кабинете [GigaChat API](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api); вводите строку без префикса `Basic`. Для DeepSeek нужен ключ его API. Ключи сохраняет Python в системном хранилище паролей через `keyring`; если оно недоступно, сохранение ключа не выполняется. Параметры подключений записываются в `~/.config/ai-tracker/providers.json` (можно изменить каталог через `AI_TRACKER_CONFIG_DIR`). SvelteKit не хранит ключи и не возвращает их в браузер после сохранения.

В настройках можно добавить другой сервис формата OpenAI Chat Completions: публичный HTTPS-адрес, заканчивающийся на `/chat/completions`, ID модели и API-ключ. Новые подключения сохраняются после перезапуска. Ключ будет отправляться на указанный вами адрес API при проверке.

Если удобнее использовать переменные среды, `GIGACHAT_AUTH_KEY` и `DEEPSEEK_API_KEY` служат запасным источником ключа для встроенных подключений. Ключ, сохранённый в настройках, имеет приоритет. Старую переменную `GIGACHAT_AUTH_KEY` можно оставить без изменений или перенести ключ в настройки.

GigaChat также требует [корневой сертификат НУЦ Минцифры](https://developers.sber.ru/docs/ru/gigachat/certificates) для HTTPS-подключения. Скачайте PEM-сертификат по ссылке из официальной инструкции Сбера. Чтобы Python доверял и обычным сайтам, и GigaChat, добавьте его к стандартному набору сертификатов из `certifi`:

```sh
cp "$(cd backend && uv run python -m certifi)" .gigachat-ca-bundle.pem
cat /путь/к/russian_trusted_root_ca_pem.crt >> .gigachat-ca-bundle.pem
export SSL_CERT_FILE="$PWD/.gigachat-ca-bundle.pem"
```

Замените `/путь/к/...` на путь к скачанному файлу. Если вы уже используете PEM-набор доверенных сертификатов с корневым сертификатом Минцифры, укажите его полный путь в `SSL_CERT_FILE`. [HTTPX читает эту переменную](https://www.python-httpx.org/environment_variables/) и продолжает проверять сертификаты; отключать проверку TLS не нужно.

Для GigaChat по умолчанию используется `GIGACHAT_API_PERS`; другой тип доступа можно выбрать в настройках. При использовании переменных среды также поддерживается `GIGACHAT_SCOPE` (`GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`).

На главной странице выберите от 1 до 5 настроенных моделей, укажите название бренда, до 20 вопросов по одному на строку и, если нужно, домен для контекста. Приложение отправляет вопросы по очереди и показывает ответы отдельно для каждой модели. Ошибки API отмечаются отдельно и не считаются отсутствием упоминания.

Результат — срез на момент проверки. При повторном запросе ответ модели может измениться. Приложение не обращается к поиску, не проверяет ссылки и не рассчитывает видимость сайта в интернете. Ответы не сохраняются в базе данных; сохранённый ключ не возвращается в браузер после настройки.

## Проверки

Тесты фронтенда находятся в `frontend/tests/`, тесты Python API — в `backend/tests/`.

```sh
make test
make check
make build
```
