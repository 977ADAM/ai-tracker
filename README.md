# ИИ-трекинг

Локальное приложение для проверки упоминаний бренда в ответах ИИ-моделей и сайта — в первой
десятке выдачи Яндекса.

## Что умеет

- **Проверка бренда.** Задайте до 20 вопросов клиентов, выберите подключённые модели и
  посмотрите, встречается ли название бренда в ответах: сводка, таблица «вопрос × модель» и
  исходные ответы.
- **Поиск сайта в Яндексе.** Добавьте от одного до пяти регионов и укажите сайт — приложение
  отправит отложенные запросы в Yandex Search API и покажет, попадает ли сайт в первую десятку
  выдачи по каждому вопросу и региону.

Ветки независимы: можно проверить только модели, только выдачу или всё сразу. Модели отвечают,
пока Яндекс ещё считает, и ошибка одной ветки не стирает результаты другой.

## Установка и запуск

```bash
make install       # Python-зависимости (uv) и Node-зависимости (npm ci)
make backend       # Python API на 127.0.0.1:8000
make frontend      # интерфейс на 127.0.0.1:5173
```

`make check` проверяет Svelte и TypeScript, `make build` собирает интерфейс,
`make frontend-prod` поднимает уже собранный.

## Ключи

Ключи моделей вводятся в приложении («Настройки API») и лежат в системном хранилище ключей:
они не попадают ни в `providers.json`, ни в ответы API, ни в текст ошибок.

Поиск в Яндексе требует ключ и каталог Yandex Cloud в окружении **серверной части** — в
корневом `.env` или в переменных оболочки. Явно заданная переменная сильнее файла.

| Переменная | Назначение |
| --- | --- |
| `YANDEX_SEARCH_API_KEY` | API-ключ сервисного аккаунта с доступом к Search API |
| `YANDEX_SEARCH_FOLDER_ID` | Каталог Yandex Cloud |

Прежние имена `API_KEY` и `FOLDER_ID` работают как запасные. Без ключей форма открывается и
проверка моделей работает, а запуск поиска отвечает понятной ошибкой «Не заданы ключ и каталог
для поиска Яндекса». Браузер ключей не видит: он обращается только к своим роутам SvelteKit.

## Как проверяется выдача

- Регионы берутся из справочника приложения (Москва и Московская область, Москва,
  Санкт-Петербург, Екатеринбург, Новосибирск и другие): от одного до пяти на запуск, без повторов.
- Один запуск — это максимум 20 вопросов × 5 регионов = **100 платных отложенных запросов**.
  Форма показывает их число до отправки.
- Совпадением считается сам хост и его поддомены: `example.ru` совпадёт с `www.example.ru`, но не
  с `example.ru.attacker.test`. Схема, путь, query и порт на совпадение не влияют.
- Вопрос для поиска ограничен 400 символами (у моделей лимит 500). Язык поиска — русский,
  регион влияет на ранжирование, но не гарантирует выдачу только из этого региона.
- Проверяется первая десятка органических результатов XML-выдачи (отложенный режим
  `/v2/web/searchAsync`, страница 0) — не реклама и не персонализированная страница браузера.

## Ограничения отложенного режима

- Поиск занимает от нескольких минут до нескольких часов. Пока страница открыта, она опрашивает
  локальный статус каждые 30 секунд.
- Задачи живут только в памяти процесса: перезагрузка страницы, закрытие вкладки и перезапуск
  сервера теряют доступ к результатам. Истории, хранилища в браузере и уведомлений нет.
- Ошибка запроса не означает, что сайта нет в выдаче: такие пары считаются отдельно, а сбой одной
  пары не мешает остальным.
- Результат — срез на момент проверки. Приложение не делает выводов о видимости сайта в интернете
  в целом.
