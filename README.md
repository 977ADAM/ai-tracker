# ИИ-трекинг

Локальное приложение для повторяемых замеров видимости бренда в ответах ИИ-моделей
и, по выбору, в первой десятке выдачи Яндекса.

## Мультикомпанийность

Приложение поддерживает несколько компаний одновременно: **каждая компания
ведётся в отдельном проекте** со своим брендом и сайтом. На главной отображаются
карточки всех проектов; можно переключаться между компаниями и запускать для
них независимые замеры.

Запросы, конкуренты, выбранные модели, отчёты и история принадлежат своему
проекту. Замер одной компании не меняет данные другой; динамика сравнивается
только внутри одного проекта. Общими для приложения остаются подключения
провайдеров, ключи API и настройки служебной LLM и поисковой системы.

## Проекты

Создание проходит в мастере из шести шагов:

1. **Бренд и сайт.** Укажите только эти два поля. Проект сразу сохраняется
   как черновик; название первоначально совпадает с брендом.
2. **Описание.** Служебная модель предлагает описание по прочитанному сайту
   и варианты названия (синонимы/сокращения). Проверьте и отредактируйте их.
3. **Промпты.** Предлагается набор запросов; добавьте, удалите или исправьте строки.
4. **Конкуренты.** Проверьте предложения брендов/сайтов; этот шаг можно оставить пустым.
5. **Нейросети.** Выберите модели из общих подключений.
6. **Запуск.** Проверьте параметры и количество вызовов. Только кнопка
   «Запустить замер» начинает измерение; переход между шагами ничего не запускает.

Описание, промпты и конкурентов можно сгенерировать заново. Предложения модели
не являются проверенными фактами и не сохраняются без перехода дальше или
сохранения черновика. Генерация использует служебную LLM и до пяти публичных
страниц введённого сайта с существующими правилами обхода; до одного вызова
LLM на шаг. Если сайт или LLM недоступны, заполните поля вручную.

«Продолжить позже» сохраняет текущие заполненные параметры. Внутри проекта
кнопка «Мастер настройки» позволяет продолжить; обычная полная форма тоже доступна.
Проект можно сохранить как черновик без запросов и моделей, но такой проект
нельзя запустить. Расписания нет. Подключения — в общих «Настройках API».

Запросы повторяются при каждом замере без скрытого добавления бренда в промпт.
Лимиты: до 20 запросов, до 5 моделей и до 10 конкурентов. Каждый запрос отправляется
каждой модели: 15 × 5 = 75 ответов. Проверка Яндекса необязательна и выключена
по умолчанию. Общие подключения настраиваются кнопкой «Настройки API».

## Отчёты и динамика

Карточка показывает последний завершённый замер: долю успешных ответов с
упоминанием названия бренда или одного из его сохранённых вариантов, число упоминаний, положительную, нейтральную и
отрицательную тональность. Полученные и запланированные ответы показаны отдельно;
ошибка модели не считается отсутствием бренда. При пустом знаменателе — «—».

Тональность оценивает служебная LLM из настроек SEO-анализа: до одного
дополнительного платного вызова на ответ с упоминанием бренда или его варианта. Ошибка оценки
показывается как «не определена», а не нейтральная оценка. В полном ответе видны
оценка и подтверждающий фрагмент. Сайт в источниках и домен в тексте — отдельные
метрики; они не увеличивают число упоминаний названия бренда.

Внутри проекта доступны разрезы по моделям и запросам, конкуренты, позиция бренда,
цитируемые источники и необязательная выдача Яндекса. Модели без веб-поиска не
получают выдуманных цитат. Веб-поиск DeepSeek использует прежний настроенный режим.

Замер сохраняет снимок настроек без ключей. Изменение проекта влияет только
на будущие запуски. Сравниваются завершённые замеры одной серии с полным покрытием;
изменение запросов, моделей или измеряемых параметров начинает новую серию.
Динамика видимости показана в процентных пунктах. Тональность сравнивается только
при наличии всех оценок. Перестановка запросов или переименование проекта серию
не меняет.

## Отмена и сохранность данных

Можно отменить активный замер: готовые данные сохраняются, новые платные вызовы
останавливаются. Уже отправленный вызов может завершиться и быть оплачен.
После перезапуска незавершённый замер помечается «Прерван» без автоматического
повторного списания. Повторный ручной запуск создаёт отдельный замер.

На один проект допускается один активный замер. Активный проект нельзя удалить.
Удаление проекта требует подтверждения и удаляет его замеры. Старые чаты,
SEO-анализы и прежние прогоны сохранены и доступны через прежние API; в новые
проекты автоматически не преобразуются. Чата в новом интерфейсе нет.

## Установка и запуск

```bash
make install       # Python-зависимости (uv) и Node-зависимости (npm ci)
make backend       # Python API на 127.0.0.1:8000
make frontend      # интерфейс на 127.0.0.1:5173
```

`make check` проверяет типы, форматирование Prettier и правила ESLint (`make types`,
`make format-check` и `make lint` по отдельности), `make build` собирает интерфейс,
`make frontend-prod` поднимает уже собранный.

## Запуск в Docker

Две службы и один том с данными; ничего кроме Docker и compose не требуется:

```bash
docker compose up -d --build      # секреты не нужны: их вводят в интерфейсе
open http://localhost:3001/clustering/tracker/
```

- `frontend` — собранный SvelteKit (adapter-node) на порту **3001**. Он же проксирует
  `/api/*` в серверную часть на своей стороне, поэтому браузер обращается только к нему,
  и CORS не нужен.
- `backend` — FastAPI на порту **8000**, опубликован только на `127.0.0.1`. Интерфейс
  ходит в него по внутренней сети compose (`http://backend:8000`).
- `ai-tracker-data` — том с `providers.json`, `runs.sqlite3`, `seo-agents.sqlite3`,
  `seo-settings.json` и файлом ключей. Данные переживают пересоздание контейнеров.

`make docker-up`, `make docker-down`, `make docker-logs` делают то же самое из Makefile.

Переменные окружения — те же, что у локального запуска (таблица ниже), плюс три для
развёртывания:

| Переменная | Назначение |
| --- | --- |
| `AI_TRACKER_ORIGIN` | Публичный origin для абсолютных ссылок и перенаправлений adapter-node; Docker Compose передаёт его как `ORIGIN` (по умолчанию `http://localhost:3001`) |
| `AI_TRACKER_ALLOWED_HOSTS` | Имена, по которым принимается API, через запятую (по умолчанию `localhost,127.0.0.1`; в compose добавлено `backend`) |
| `AI_TRACKER_API_HOSTS` | Хосты, к которым BFF вправе обращаться с сервера, через запятую; loopback разрешён всегда |

Docker-образ интерфейса собран для пути `/clustering/tracker`, чтобы Angie мог разместить его
рядом с другим приложением. Доступ к порту `3001` открыт только на `127.0.0.1`; при запуске
на сервере установите `AI_TRACKER_ORIGIN` в публичный origin (схема и домен без пути), а
Angie направьте на `http://127.0.0.1:3001` весь префикс `/clustering/tracker/` без его удаления.

Приложение можно поднять без единого секрета: `docker compose up -d --build` стартует с пустой
конфигурацией, а ключи и адреса вводятся в интерфейсе («Настройки API») и сохраняются в томе.
Если удобнее задавать их переменными окружения, положите рядом с `docker-compose.yml` файл
`.env` — compose читает его сам, — но значение, сохранённое в интерфейсе, сильнее окружения. Адрес, по
которому открыт интерфейс, значения не имеет — `http://localhost:3001` и `http://127.0.0.1:3001`
работают одинаково, потому что запросы, меняющие состояние, сверяются с адресом, по которому их
прислал браузер.

### Ключи в контейнере

В контейнере нет системного хранилища ключей macOS или Linux, поэтому образ backend
ставит файловый бэкенд (`keyrings.alt`) и складывает ключи, сохранённые через интерфейс,
в том: `.local/share/python_keyring/keyring_pass.cfg` с правами `0600` и владельцем —
пользователем контейнера. Поэтому свежий том можно поднять пустым, а все ключи — модели,
Яндекс и служебная LLM — вводить прямо в интерфейсе: они переживут пересоздание контейнеров. Файл не шифрует значения, поэтому ключи, которые не должны
лежать на диске, задавайте переменными окружения: `YANDEX_SEARCH_API_KEY`,
`YANDEX_SEARCH_FOLDER_ID`, `SEO_LLM_ENDPOINT`, `SEO_LLM_MODEL`, `SEO_LLM_API_KEY`.
Переменная `DEEPSEEK_API_KEY` работает как запасной источник для подключения с
идентификатором `deepseek`.

## Ключи

Ключи моделей вводятся в приложении («Настройки API») и лежат в системном хранилище ключей:
они не попадают ни в `providers.json`, ни в ответы API, ни в текст ошибок.

Кнопка «Открыть конфигурацию» в «Настройках API» показывает один документ со всем, что
приложение хранит на диске: провайдеры, настройки поисковой системы и SEO-анализа. Ключей в
нём нет — они лежат в системном хранилище; в Docker документ показывает содержимое тома.

Откройте «Настройки API» → «Поисковые системы», чтобы включить или отключить Яндекс, указать
API-ключ и ID каталога Yandex Cloud. Яндекс включён по умолчанию. При отключении региональный
поиск исчезает из доступных параметров, а проверка моделей остаётся доступной. Новые настройки
применяются к новым прогонам сразу; уже запущенные продолжают работу с исходным подключением.

Ключ Яндекса, сохранённый через интерфейс, лежит в системном хранилище ключей. ID каталога и
признак доступности лежат в `search-settings.json` в `AI_TRACKER_CONFIG_DIR` (по умолчанию
`~/.config/ai-tracker`). Ключ не возвращается в API и не записывается в JSON-файл. Пустые поля
при сохранении оставляют существующие учётные данные без изменений. Кнопка «Сбросить учётные
данные» удаляет оба значения, введённых через интерфейс, сохраняя состояние переключателя Яндекса.

Служебная LLM для SEO-анализа настраивается отдельно: «Настройки API» → вкладка «SEO-анализ».
Нужны полный адрес OpenAI-совместимого Chat Completions, название модели и API-ключ. Удалённый
адрес должен использовать HTTPS; HTTP разрешён только для loopback-адреса. Ключ хранится в
системном хранилище под отдельной учётной записью `seo-llm`, адрес и модель — в
`seo-settings.json`; публичный ответ содержит адрес, модель, признак наличия ключа и источники
значений, но никогда сам ключ. Кнопка «Проверить подключение» делает два пробных вызова и
показывает, поддерживает ли модель вызов инструментов; без этой поддержки запуск SEO-анализа
отклоняется. Пустой ключ при сохранении не стирает действующий, а сброс учётных
данных удаляет ключ интерфейса и возвращает значения окружения. Без настроенной служебной LLM
запуск SEO-анализа отвечает понятной ошибкой «Не настроена служебная LLM для SEO-анализа».

Если значение не задано в интерфейсе, сервер берёт его из окружения **серверной части** —
корневого `.env` или переменных оболочки. Явно заданная переменная сильнее `.env`.

| Переменная | Назначение |
| --- | --- |
| `YANDEX_SEARCH_API_KEY` | API-ключ сервисного аккаунта с доступом к Search API |
| `YANDEX_SEARCH_FOLDER_ID` | Каталог Yandex Cloud |
| `SEO_LLM_ENDPOINT` | Адрес Chat Completions служебной LLM |
| `SEO_LLM_MODEL` | Модель служебной LLM |
| `SEO_LLM_API_KEY` | API-ключ служебной LLM |

Прежние имена `API_KEY` и `FOLDER_ID` работают как запасные. Если после сброса не осталось
значений окружения, проверка моделей продолжает работать, а запуск поиска отвечает понятной
ошибкой «Не заданы ключ и каталог для поиска Яндекса». Браузер ключей не видит: он обращается
только к своим роутам SvelteKit.

## Как проверяется выдача

- Регионы берутся из справочника приложения (Москва и Московская область, Москва,
  Санкт-Петербург, Екатеринбург, Новосибирск и другие): от одного до пяти на запуск, без повторов.
- Один запуск прежнего сценария — это максимум 20 вопросов × 5 регионов = **100 платных
  отложенных запросов**. Число запросов известно до отправки. SEO-анализ использует свои
  правила и свой фиксированный лимит в 7 сгенерированных запросов; старые лимиты не меняются.
- Совпадением считается сам хост и его поддомены: `example.ru` совпадёт с `www.example.ru`, но не
  с `example.ru.attacker.test`. Схема, путь, query и порт на совпадение не влияют.
- Вопрос для поиска ограничен 400 символами (у моделей лимит 500). Язык поиска — русский,
  регион влияет на ранжирование, но не гарантирует выдачу только из этого региона.
- Проверяется первая десятка органических результатов XML-выдачи (отложенный режим
  `/v2/web/searchAsync`, страница 0) — не реклама и не персонализированная страница браузера.

## Ограничения отложенного режима

- Поиск занимает от нескольких минут до нескольких часов. Страница опрашивает локальный статус
  каждые 30 секунд, а полученные результаты сохраняются сразу.
- История хранится в `runs.sqlite3` в каталоге `AI_TRACKER_CONFIG_DIR` (по умолчанию
  `~/.config/ai-tracker`) без автоматического удаления. После перезапуска сервера готовые строки
  остаются: прогон с чекпойнтом продолжается с сохранёнными результатами, а прогон без чекпойнта
  помечает незавершённые строки прерванными и не отправляет их повторно.
- Завершённый, ошибочный, прерванный или отменённый прогон остаётся в чате: его отчёт
  открывается по кнопке, а удаляется прогон вместе со своим чатом. Прежний прогон дополнительно
  можно выгрузить в CSV. Активный прогон нельзя удалить или экспортировать.
- Прямой API `/api/search` сохранён для совместимости и по-прежнему хранит задачи только
  в памяти процесса; чат запускает сохраняемые прогоны через `/api/seo/chats`, а прежние
  SEO-прогоны остаются доступны только через API `/api/seo/analyses`.
- Ошибка запроса не означает, что сайта нет в выдаче: такие пары считаются отдельно, а сбой одной
  пары не мешает остальным.
- Результат — срез на момент проверки. Приложение не делает выводов о видимости сайта в интернете
  в целом.
