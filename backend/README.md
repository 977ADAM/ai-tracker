# ИИ-трекинг API

Локальный Python API для проверки упоминаний бренда в ответах ИИ-моделей. Общие инструкции по запуску находятся в [корневом README](../README.md).

## Слои

```
app/
├── main.py          композиционный корень: собирает `app` на уровне модуля
├── core/            сквозные вещи: Settings, иерархия безопасных ошибок
├── domain/          чистые правила: модели, лимиты, валидация, матчинг, отчёт
├── db/              персистентность: providers.json и системное хранилище ключей
├── service/         сценарии: подключения, проверка, конфигурация формы
├── integrations/    исходящие адаптеры: GigaChat, OpenAI-совместимый API, фабрика
└── api/             входящий HTTP: роутеры, зависимости, отображение ошибок
```

`main.py` не содержит фабрики: приложение собирается один раз при импорте, поэтому
`uvicorn app.main:app` не требует вызова. Там же регистрируются middleware, обработчики
ошибок и роутер с префиксом `/api`, а собранные зависимости лежат в `app.state`.

Зависимости направлены внутрь: `api → service → domain`, а `db` и `integrations` реализуют
протоколы, объявленные в `domain`. `domain` и `core` не импортируют FastAPI, httpx или keyring.

Ключи API никогда не покидают `db`: они уходят в системное хранилище (`keyring`, сервис
`ai-tracker`) и не попадают ни в `providers.json`, ни в ответы API, ни в текст ошибок.

## Запуск

```bash
uv sync
uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Тот же запуск доступен через `make backend` из корня репозитория.

## Тесты

```bash
uv run pytest
```

Конфигурация pytest живёт в `pyproject.toml` (`pythonpath = ["."]`), поэтому импорт `app`
работает без переменных окружения.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `AI_TRACKER_CONFIG_DIR` | Каталог с `providers.json`. По умолчанию `~/.config/ai-tracker` |
| `GIGACHAT_AUTH_KEY` | Запасной ключ для подключения с ID `gigachat` |
| `DEEPSEEK_API_KEY` | Запасной ключ для подключения с ID `deepseek` |
| `GIGACHAT_SCOPE` | Область доступа GigaChat по умолчанию |

Сохранённый в настройках ключ всегда имеет приоритет над переменной окружения.

## Встроенные подключения

`core/config.py:BUILTIN_PRESETS` пуст: приложение не поставляет предустановленных подключений,
и все подключения создаёт пользователь на экране настроек. Чтобы вернуть шаблоны, достаточно
заполнить этот кортеж — код пресетов (область доступа GigaChat, сброс ключа, только
редактируемый ключ) уже покрыт тестами.

## HTTP API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/form` | Лимиты, поля нового подключения, области доступа, выбор по умолчанию |
| `GET` | `/api/providers` | Список подключений без ключей |
| `POST` | `/api/providers` | Создать OpenAI-совместимое подключение |
| `PUT` | `/api/providers/{id}` | Изменить подключение; пустой ключ сохраняет прежний |
| `DELETE` | `/api/providers/{id}` | Удалить подключение и его ключ |
| `POST` | `/api/check` | Прогнать выбранные подключения по одним и тем же запросам |

`POST /api/check` требует `provider_ids` из 1–5 разных сохранённых ID: сервер не принимает
ни адреса, ни ключи из тела запроса. Ответ содержит `checks[]` с группой на каждое
подключение, общий `summary` и плоский список `rows`.

Ошибки возвращаются как `{"detail": "<понятный текст>"}`: 400 — некорректный запрос или
настройки, 503 — недоступное локальное хранилище.
